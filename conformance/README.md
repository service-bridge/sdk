# conformance

## Зона ответственности

Сценарии поведения, общие для всех SDK. Каждый сценарий описан один раз в YAML и прогоняется против живого runtime во всех парах «вызывающий SDK → вызываемый SDK» (go→go, go→node, node→go, node→node). Код SDK здесь не лежит, только сценарии.

## Публичный контракт

Файлы `scenarios/*.yaml`, в каждом ключ `scenarios` со списком сценариев.

| Имя | Тип | По умолчанию | Что делает |
|-----|-----|--------------|------------|
| `name` | string | — | Имя сценария, становится именем подтеста. |
| `caller.deps` | []string | `[]` | Методы, которые вызывающий объявляет зависимостями, хотя вызываемый их не регистрирует. |
| `caller.events` | []string | `[]` | События, которые вызывающий объявляет для публикации. |
| `callee.rpc[].method` | string | — | Метод вызываемого. |
| `callee.rpc[].behaviour` | `echo` \| `info` \| `{sleepMs}` \| `{fail: {code, message}}` \| `{throw: message}` | — | Что делает обработчик. `echo` возвращает `text`, `n` и `handledBy` = имя SDK. `info` возвращает `text` = service id вызывающего, `n` = остаток дедлайна в мс, `handledBy` = ключ идемпотентности. `sleepMs` ждёт, потом отвечает как `echo`. `fail` бросает HandlerError с бизнес-кодом. `throw` бросает обычную ошибку. |
| `callee.subscriptions[]` | `{pattern, filter?}` | `[]` | Подписки вызываемого. `filter` имеет вид `{"$.path": literal}`. |
| `steps[].call` | `{method, payload, transport?, timeoutMs?, idempotencyKey?}` | — | Вызов от вызывающего к вызываемому. |
| `steps[].expect.reply` | `{text?, n?, nMin?, nMax?, handledBy?}` | — | Ожидаемый ответ. В строках можно писать `$caller.serviceId` и `$callee.sdk`. |
| `steps[].expect.error` | `{code, handlerCode?, handlerMessage?, retryable?}` | — | Ожидаемая ошибка по модели ошибок SDK (см. `../README.md`). |
| `steps[].expect.served` | int | не проверяется | Сколько раз обработчик вызываемого отработал этот метод. |
| `steps[].publish` | `{event, payload, partitionKey?}` | — | Публикация от вызывающего. Успех означает, что runtime вернул event id. |
| `steps[].deliveries` | `[{pattern, event, orderId, amount?, currency?}]` | — | Ровно этот набор доставок вызываемому, по одной на пару (pattern, event). Лишняя доставка — ошибка. |

Имена методов, событий и паттернов в YAML относительные. Раннер добавляет к ним пространство имён сценария и пары, поэтому прогоны не пересекаются. Схема — `Echo`/`EchoReply` и `OrderEvent` из `go/tests/e2e/testdata/e2e.proto`.

## Приватный контракт

| Имя | Тип | По умолчанию | Что делает |
|-----|-----|--------------|------------|
| `go/tests/e2e/conformance_test.go` | Go test `TestConformance` | — | Читает YAML, поднимает обе роли, выполняет шаги и сверяет результат. Go-роль работает в процессе теста. |
| `go/tests/e2e/nodeagent/conformance.ts` | Bun-скрипт | — | Node-роль. Конфигурация приходит JSON в `SB_AGENT_CONFIG`, команды (`call`, `publish`, `awaitMethod`, `stop`) идут по stdio строками JSON, наблюдения (`served`, `delivery`) возвращаются тем же путём. |
| `conformance` в `scripts/bootstrap-e2e-keys.sh` | домен ключей | — | Сервисы `e2e-conformance-1` (вызывающий) и `e2e-conformance-2` (вызываемый). |

## Архитектурные решения и почему

- Сценарии лежат отдельно от тестов обоих SDK. Если ожидание записано в тестах одного SDK, второй может с ним разойтись и этого никто не заметит.
- Раннер один, на Go. Node-роль — процесс-агент, который обслуживает такой же протокол, как и Go-агент в процессе. Второй раннер на TypeScript проверял бы те же пары во второй раз.
- Все пары используют одни и те же два сервиса по очереди. Перед стартом каждой пары предыдущие клиенты останавливаются, а уникальные имена исключают трафик между парами.
- Проверка «лишних» доставок ждёт одну секунду после прихода ожидаемых. Событию, которое не должно прийти, ждать нечего, а повторная доставка (at-least-once) с тем же содержимым не считается лишней.

## Зависимости

Опирается на: runtime (живой, адрес и ключи из `.env.e2e`), `go.yaml.in/yaml/v3` (только в тестах), Go SDK, Node SDK из `node/src`. На эти сценарии опирается: CI-джоба Go e2e (`go test -tags e2e ./tests/e2e/...`) и `runtime/scripts/ci-local.sh`.
