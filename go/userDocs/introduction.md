## Что такое ServiceBridge

ServiceBridge — self-hosted рантайм для микросервисов: один Go-бинарь плюс PostgreSQL вместо связки из service mesh, брокера сообщений, движка workflow, планировщика и стека трассировки.

Сервис объявляет, что он обрабатывает и что вызывает, после чего стартует. Дальше рантайм берёт на себя транспорт, доставку событий, оркестрацию, политику доступа и observability. Sidecar-прокси нет: SDK сам провижинит mTLS-идентичность и открывает соединение.

```
        ДО                                          ПОСЛЕ

  ┌─────────────────────┐
  │  Istio + Envoy      │  ← mesh / mTLS
  │  RabbitMQ / Kafka   │  ← события                ┌──────────────────────┐
  │  Temporal           │  ← workflow               │                      │
  │  планировщик cron   │  ← задачи                 │   ServiceBridge      │
  │  обвязка gRPC       │  ← RPC          ═══►      │   рантайм (1 бинарь) │
  │  Jaeger / Tempo     │  ← трассировка            │          +           │
  │  обвязка Prometheus │  ← метрики                │      PostgreSQL      │
  │  Loki               │  ← логи                   │                      │
  │  балансировщик      │  ← LB / ретраи            └──────────────────────┘
  │  реестр сервисов    │  ← discovery
  └─────────────────────┘
```

## Чем ServiceBridge не является

- **Не прокси для бизнес-HTTP.** Свой `net/http`, chi или gin-сервер запускает приложение. Интеграция `sbhttp` только публикует список роутов в Service Map и оборачивает запрос в спан. Трафик через рантайм не идёт.
- **Не sidecar.** Отдельного процесса рядом с сервисом нет; вся клиентская часть — это библиотека в вашем бинаре.
- **Не замена вашей БД.** Рантайму нужен PostgreSQL для собственного состояния; данные приложения он не трогает.
- **Не фреймворк приложения.** SDK не диктует структуру проекта, не поднимает HTTP-сервер и не читает переменные окружения.

## Что делает Go SDK

### Связь

- **Direct RPC** — запрос/ответ поверх mTLS напрямую между инстансами, с балансировкой, ретраями и размыкателем на стороне вызывающего.
- **Proxy RPC** — тот же вызов через рантайм, когда инстанс должен резолвить и заявку идемпотентности держать рантайм.
- **Server-side streaming** — потребление через `iter.Seq2` и обычный `range`.
- **Durable events** — публикация at-least-once через локальный SQLite-outbox, подписка через двунаправленный стрим.
- **Service discovery и Service Map** — живой список инстансов и методов, который рантайм проталкивает клиенту.

### Оркестрация

- **Workflows** — durable DAG: шаги переживают рестарт, компенсируются в обратном порядке при сбое или отмене, умеют ждать событие или сигнал.
- **Jobs** — cron, интервал и одноразовый запуск. Расписание, лиз и ретраи держит рантайм.

### Надёжность

- Доставка at-least-once, ретраи, DLQ, идемпотентность, веерная рассылка, переживание разрыва сессии, отказоустойчивость по нескольким инстансам, размыкатели.

### Observability

- Каждый RPC, событие, задача, шаг workflow и HTTP-запрос уже создают операцию и протягивают трассировку между хопами.
- `c.Telemetry` добавляет собственные операции, счётчики, gauge и гистограммы.
- Логи — обычный `*slog.Logger`, который подключается в вашу цепочку `slog`.

### Безопасность

- TLS по умолчанию, mTLS-идентичность, сертификаты провижинятся из bootstrap-ключа сервиса и ротируются с перекрытием.
- Гранулярная политика доступа — на стороне рантайма; SDK показывает её результат.

### Схемы

Схема RPC-метода и события берётся **из сгенерированного protobuf-типа**. Файл `.proto` рядом с бинарём не нужен, шага «зарегистрировать схему» нет: SDK читает дескриптор из сгенерированной структуры и выводит из него JSON Schema и хеш контракта.

## Что НЕ входит в SDK

- **Чтение конфигурации.** SDK не читает ни одной переменной окружения. Адрес рантайма, ключ сервиса и все настройки — аргументы `sb.New`.
- **Свой HTTP-сервер.** Его поднимает приложение.
- **Управление DLQ.** Повторная доставка и разбор «мёртвых» сообщений живут в дашборде рантайма.
- **Редактирование политики доступа.** SDK её только наблюдает.
- **Генерация protobuf-кода.** Типы генерируются вашим обычным `protoc` / `buf`.

## Требования

| | Минимум |
|--|--|
| Go | 1.24 |
| Рантайм ServiceBridge | gRPC control plane на `:14445` |
| PostgreSQL | 18+ (нужен рантайму, не SDK) |
| cgo | не требуется — драйвер SQLite чисто на Go, сборки с `CGO_ENABLED=0` работают |

Модуль тянет за собой gRPC, protobuf, `robfig/cron/v3`, `google/uuid`, `go-chi/chi/v5` и `modernc.org/sqlite`. gin в основной модуль не входит — он живёт в отдельном модуле `sbgin`, потому что в Go нет необязательных зависимостей.
