## 1. Конструктор и опции

```go
func build() (*sb.Client, error) {
	return sb.New("localhost:14445", os.Getenv("ORDERS_KEY"),
		sb.WithAdvertise(os.Getenv("POD_IP"), 50051),
		sb.WithCallDefaults(sb.WithTimeout(10*time.Second)),
		sb.WithCallAttempts(3),
		sb.WithMaxPendingPublishes(50_000),
		sb.WithPublishTimeout(10*time.Second),
		sb.WithInboundLimits(256, 256),
		sb.WithReconnectLadder(time.Second, 5*time.Second, 30*time.Second),
	)
}
```

`sb.New` **не делает ввода-вывода**. Всё, что не так с конфигурацией, сообщается здесь же, с кодом `CodeConfig`: неверная граница не должна выглядеть как сетевое условие и бесконечно кормить лестницу переподключения.

Адрес принимается в виде `host:port`; схема вида `https://` и завершающий `/` отбрасываются.

**SDK не читает ни одной переменной окружения.** Откуда берутся адрес, ключ и всё остальное — решаете вы.

| Опция | По умолчанию | Что делает |
|---|---|---|
| `WithAdvertise(host, port)` | `127.0.0.1`, порт `0` | Адрес, который набирают для прямого RPC. Порт `0` просит свободный у ОС и объявляет выданный. В контейнере передавайте реальный адрес: значение объявляется как есть. |
| `WithCallerOnly()` | выключено | Только исходящий инстанс: входящий слушатель не поднимается, регистрация обработчика запрещена. Противоречит `WithAdvertise`. |
| `WithCallDefaults(opts...)` | таймаут `30s`, `TransportAuto` | `CallOption`, применяемые к каждому вызову, который их не перекрыл, — на всех путях вызова. |
| `WithCallAttempts(n)` | `3` | Всего попыток одного логического вызова, считая первую: три — это один вызов и два повтора. Повторяются только доказанные отказы до отправки. |
| `WithFailOnPolicyViolation()` | выключено | Останавливать клиент при нарушении политики, а не только сообщать о нём. |
| `WithMaxPendingPublishes(n)` | `10000` | Размер очереди публикаций в памяти; на пределе `PublishEvent` сразу возвращает `CodeQueueFull`. |
| `WithPublishTimeout(d)` | `30s` | Предел одной публикации от постановки в очередь до подтверждения рантайма; дальше — `CodeTimeout`. |
| `WithMaxInFlightEvents(n)` | `32` | Одновременно обрабатываемых входящих доставок. На пределе стрим доставок перестаёт вычитываться — это и есть backpressure. |
| `WithInboundLimits(calls, queued)` | `256` / `256` | Одновременно работающих обработчиков и вызовов, ждущих свободного. За обеими границами вызывающий получает `RESOURCE_EXHAUSTED` с доказательством «не отправлено» и повторяет на другом инстансе. HTTP/2-стримов на соединение — не больше суммы. |
| `WithReconnectAttempts(n)` | `0` — без предела | Предел подряд идущих неудачных переподключений; счётчик сбрасывается на каждой успешной сессии. Сервис, сдавшийся посреди rolling restart, — это сервис, к которому придётся идти руками. |
| `WithReconnectLadder(rungs...)` | `1s, 5s, 15s, 30s, 60s` | Задержки переподключения. Последняя ступень повторяется бесконечно, каждая — с джиттером ±20 %. |
| `WithTelemetryDropHandler(fn)` | нет | Вызывается с `sb.TelemetryDrop` — сколько телеметрии потеряно с прошлого отчёта: `ServerDrops` (сброшено рантаймом под нагрузкой), `RingDrops` (вытеснено из локального буфера), `BackpressureLevel`. Те же числа уходят в рантайм метрикой `sb_sdk_telemetry_dropped_total{source}`. |
| `WithLogger(log)` | `slog.Default()` | Куда SDK пишет собственную диагностику. |

Значения по умолчанию экспортированы константами: `sb.DefaultCallTimeout` (30 с), `sb.DefaultCallAttempts` (3), `sb.DefaultMaxPendingPublishes` (10000), `sb.DefaultPublishTimeout` (30 с), `sb.DefaultMaxInFlightEvents` (32), `sb.DefaultMaxConcurrentCalls` (256), `sb.DefaultMaxQueuedCalls` (256), `sb.DefaultStopTimeout` (10 с), `sb.DefaultAdvertiseHost` (`127.0.0.1`).

### Что отвергается сразу

`CodeConfig` из `sb.New` получают: пустой адрес рантайма; неразбираемый bootstrap-ключ; `WithCallerOnly` вместе с `WithAdvertise`; пустой хост при не-caller-only; порт вне `0..65535`; неположительные размер очереди публикаций, таймаут публикации, предел доставок, предел одновременных вызовов и бюджет попыток; отрицательная очередь входящих вызовов; отрицательный предел переподключений; неположительный таймаут вызова по умолчанию; неизвестный транспорт; нулевой логгер; неположительная ступень лестницы.

### Типичные наборы

```go
func callerOnly(key string) (*sb.Client, error) {
	// Процесс, который только вызывает: cron-утилита, скрипт миграции, шлюз.
	return sb.New("localhost:14445", key, sb.WithCallerOnly())
}
```

```go
func inKubernetes(key string) (*sb.Client, error) {
	// Под, который обслуживает RPC. Адрес обязателен: loopback по умолчанию
	// объявится как есть, и до пода никто не дозвонится.
	return sb.New("servicebridge.svc.cluster.local:14445", key,
		sb.WithAdvertise(os.Getenv("POD_IP"), 50051),
		sb.WithFailOnPolicyViolation(),
	)
}
```

```go
func highVolumePublisher(key string) (*sb.Client, error) {
	// Много публикаций: очередь переживает более долгий разрыв с рантаймом.
	return sb.New("localhost:14445", key,
		sb.WithCallerOnly(),
		sb.WithMaxPendingPublishes(200_000),
		sb.WithPublishTimeout(2*time.Minute),
	)
}
```

## 2. Жизненный цикл: Start и Stop

```go
func lifecycle(ctx context.Context, key string) error {
	c, err := sb.New("localhost:14445", key)
	if err != nil {
		return err
	}

	// объявления: обработчики, зависимости, события, задачи, workflow
	if err := sb.Handle(c, "Ship", shipHandler); err != nil {
		return err
	}
	payment := sb.NewClient(c, "payment-svc")
	if _, err := sb.NewMethod[*paymentpb.ChargeRequest, *paymentpb.ChargeReply](payment, "Charge"); err != nil {
		return err
	}

	if err := c.Start(ctx); err != nil {
		return err
	}
	defer func() { _ = c.Stop(ctx) }()

	// ... работа ...
	return nil
}
```

### Что делает Start

В единственном порядке, который работает:

1. Проверяет, что каждый шаг `wf.Call` в объявленных workflow называет объявленную зависимость.
2. Запечатывает объявления — с этого момента mesh знает, что существует.
3. Объявляет подписки на события вместе с их фильтрами.
4. Регистрирует всех держателей mTLS-материала, чтобы первый же сертификат дошёл до каждого.
5. Отдаёт управление жизненному циклу: тот провижинит сертификат (или переиспользует кэшированный), поднимает входящий сервер, открывает управляющую сессию, дожидается от рантайма `Welcome` и только потом стартует поток реестра — адрес слушателя обязан лежать уже в самом первом кадре регистрации, иначе mesh будет звонить туда, где никто не слушает.
6. Дожидается первого снапшота реестра — это и есть подтверждение регистрации.
7. Поднимает отправителя публикаций, телеметрию и подписки, которым нужна зарегистрированная идентичность.

На всё это у `Start` не больше 30 секунд. При сбое `Start` останавливает всё, что успел поднять, и возвращает ошибку.

**Клиент переживает контекст, переданный в `Start`.** Его отмена отбрасывается, а значения сохраняются: контекст уровня запроса не должен уметь положить клиент. Опускать клиент — задача `Stop`.

Повторный `Start` — `CodeState`. `Start` после `Stop` — тоже.

### Ready

`c.Ready(ctx)` блокируется, пока текущая сессия не жива и не применила снапшот реестра. Сразу после `Start` возвращается мгновенно; во время переподключения ждёт новой сессии. До `Start` и после `Stop` — `CodeState`.

### Переподключение

Потерянная сессия восстанавливается по лестнице `WithReconnectLadder`; по умолчанию предела попыток нет. Счётчик неудач сбрасывается на каждом `Welcome`. Пока сессии нет, публикации ждут в очереди и уходят под своими id, когда она вернётся.

Клиент останавливается окончательно (`OnDisconnected`) только на отказах, которые повтор не исправит: рантайм отверг учётные данные, не знает сервис, отверг регистрацию (например, невалидный фильтр подписки) или говорит на другой версии протокола.

`Drain` от рантайма — штатная ситуация: срабатывает `OnDraining`, и клиент переподключается, когда рантайм закроет сессию.

### Что делает Stop

Останавливает клиент в порядке, который не теряет ничего, что можно сохранить:

1. **Дренаж.** Входящий сервер отказывает новым вызовам с `UNAVAILABLE` и доказательством «не отправлено», инстанс перерегистрируется без адреса для вызовов, чтобы пиры перестали на него маршрутизировать, подписчики событий и задач перестают брать новую работу. Невзятые доставки рантайм отдаст снова — попытки на них не тратятся.
2. Ждёт входящие вызовы, обработчики событий и задач, которые уже работают.
3. Досылает очередь публикаций; то, что не успело уйти, завершается `CodeConnection` «client stopped».
4. Сбрасывает телеметрию и ждёт подтверждения последней пачки — не дольше 2 секунд.
5. Закрывает управляющую сессию, поток реестра, каналы данных и входящий сервер.

Шаги 2 и 3 делят дедлайн `ctx`; если у `ctx` его нет — `sb.DefaultStopTimeout` (10 с). Go не умеет остановить код, игнорирующий контекст: по истечении дедлайна `Stop` отменяет контексты обработчиков и возвращает ошибку с `CodeTimeout`.

`Stop` идемпотентен и сообщает все сбои, не пропуская оставшиеся шаги.

### Мягкое завершение

```go
func serveUntilSignal(c *sb.Client) error {
	ctx := context.Background()
	if err := c.Start(ctx); err != nil {
		return err
	}

	stop := make(chan os.Signal, 1)
	signal.Notify(stop, syscall.SIGINT, syscall.SIGTERM)
	<-stop

	shutdown, cancel := context.WithTimeout(context.Background(), 30*time.Second)
	defer cancel()
	return c.Stop(shutdown)
}
```

## 3. Колбэки соединения

```go
func observe(c *sb.Client) {
	c.OnConnected(func(id sb.Identity) {
		log.Println("connected as", id.ServiceName, id.InstanceID)
	})
	c.OnReconnecting(func(attempt int, cause error) {
		log.Println("reconnecting", attempt, cause)
	})
	c.OnDraining(func(reason string) {
		log.Println("runtime is draining:", reason)
	})
	c.OnDisconnected(func(cause error) {
		log.Println("disconnected:", cause)
	})
	c.OnPolicyViolation(func(v sb.PolicyViolation) {
		log.Println("policy refused", v.Declaration, v.Value, v.Reason)
	})
}
```

| Колбэк | Когда срабатывает |
|---|---|
| `OnConnected` | Один раз на живую сессию, после `Welcome` рантайма. Продление сертификата сессию не пересоздаёт и этот колбэк не вызывает. |
| `OnReconnecting` | Перед каждой попыткой восстановить потерянную сессию. |
| `OnDraining` | Рантайм объявил, что выключается. Клиент переподключится сам, когда рантайм закроет сессию. |
| `OnDisconnected` | Один раз, когда клиент перестал пытаться переподключиться. |
| `OnPolicyViolation` | На каждое объявление, отвергнутое политикой, — и из снапшота реестра, и из отказанной публикации события. |

Колбэки выполняются на собственных горутинах клиента и **не должны блокировать**. Паника в колбэке перехватывается и логируется, остальные колбэки всё равно выполняются. Регистрировать их можно несколько на одно событие.

Нарушение политики заслуживает внимания, хотя это не ошибка: рантайм регистрирует, что может, и предупреждает об остальном, так что на проводе наполовину подключённый сервис выглядит здоровым. `c.PolicyEvaluation()` возвращает последнюю политику, которую прислал рантайм: `Capabilities` и `Warnings`.

## 4. Identity и ServiceMap

```go
func whoAmI(c *sb.Client) {
	id := c.Identity()
	log.Println(id.ServiceID, id.ServiceName, id.InstanceID, id.SessionID)
}
```

**`Identity` читайте по требованию, а не кэшируйте.** `InstanceID` стабилен при продлении сертификата, но меняется, если сертификат успел истечь и SDK провижинил его заново. Сохранённая в переменную копия в этом случае указывает на инстанс, которого уже нет.

```go
func waitForMethod(ctx context.Context, c *sb.Client, service, method string) error {
	for {
		for _, m := range c.ServiceMap().Methods {
			if m.ServiceName == service && m.Name == method {
				return nil
			}
		}
		select {
		case <-ctx.Done():
			return ctx.Err()
		case <-time.After(200 * time.Millisecond):
		}
	}
}
```

`ServiceMap` — снимок mesh на момент вызова: `Instances` (с `CallEndpoint`, `HTTPEndpoint`, `Status`, `UnhealthySinceMs`) и `Methods` (с `Type`, `ContractHash`, `Streaming`).

## 5. Входящий сервер и advertise

Входящий сервер поднимается, если клиент **не** объявлен как `WithCallerOnly`.

| Сценарий | Как настроить |
|---|---|
| Локальная разработка | Ничего: по умолчанию `127.0.0.1:0`, порт выдаёт ОС. |
| Под в Kubernetes | `sb.WithAdvertise(os.Getenv("POD_IP"), 50051)`. |
| Контейнер с проброшенным портом | Хост и порт, по которым до контейнера дозваниваются снаружи, — не те, что внутри. |
| Процесс, который только вызывает | `sb.WithCallerOnly()`. |

Что попадает в реестр: адрес для прямого RPC (`call_endpoint`), список входящих методов со схемами и хешами контрактов, публикуемые события, подписки, исходящие зависимости и — если подключён `sbhttp` — адрес HTTP-сервера с роутами.

`WithInboundLimits(calls, queued)` ограничивает входящую нагрузку: до `calls` обработчиков работают, ещё до `queued` вызовов ждут слот. Дальше вызывающий получает `RESOURCE_EXHAUSTED` с доказательством «не отправлено» и повторяет на другом инстансе. Проверки вызывающего идут до занятия слота, поэтому неавторизованный вызывающий за ёмкость не конкурирует.

До первого снапшота реестра входящий сервер отвечает `UNAVAILABLE "not ready"`: без снапшота нет правил приёма. Во время `Stop` — `UNAVAILABLE "draining"`. Оба отказа несут доказательство «не отправлено».

## 6. Безопасность: ключ, mTLS, ротация

### Bootstrap-ключ

Строка вида `sb.<base64url>` из дашборда. Внутри — идентификатор ключа, секрет и **сертификат CA**.

CA едет внутри ключа не для удобства: первое же соединение с рантаймом оказывается привязанным к известному корню, без окна доверия при первом контакте. SDK доверяет ровно этому корню и ничему из системного хранилища.

Ключ — это секрет. Держите его в `.env` (в `.gitignore`) или в менеджере секретов, передавайте в `sb.New` явно.

### Что происходит при подключении

1. SDK генерирует свежую пару ключей P-256 и запрос на сертификат.
2. Отправляет его вместе с идентификатором ключа и секретом по каналу, привязанному к CA из bootstrap-ключа.
3. Рантайм возвращает листовой сертификат с SPIFFE-идентичностью инстанса.
4. Дальше всё общение идёт по mTLS этим сертификатом.

Один и тот же ключ можно использовать в нескольких процессах: каждый получит свою идентичность инстанса при общем `ServiceID`.

### Продление сертификата

Сертификат продлевается **заранее**, а не по истечении: за 30 минут до конца срока, со случайным разбросом до 5 минут, чтобы весь флот не пошёл обновляться одновременно. Продление идёт по живой управляющей сессии.

Продление происходит на месте: `InstanceID` не меняется, ни сессия, ни потоки, ни каналы, ни входящий сервер не пересоздаются. Новый сертификат предъявляют новые соединения, живые продолжают работать. Неудачное продление ничего не меняет: клиент остаётся на текущем сертификате и повторяет попытку через 60 секунд.

Если сертификат всё же истёк, SDK провижинит новый — это новый инстанс с новым `InstanceID`, и только тогда каналы к пирам пересобираются.

Сертификат кэшируется **только в памяти**. На диск SDK ничего не пишет.

Скомпрометированный ключ отзывается в рантайме; после этого сервису нужен новый ключ и перезапуск с ним. Отзыв сервиса или инстанса действует сразу: пиры перестают его выбирать и закрывают к нему каналы, его входящие вызовы получают `PERMISSION_DENIED`.

## 7. Телеметрия

Каждый RPC, событие, задача, шаг workflow и HTTP-запрос уже создают операцию и протягивают трассировку между хопами. `c.Telemetry` добавляет ваши собственные.

```go
func instrumented(ctx context.Context, c *sb.Client, cartID string) error {
	ctx, op := c.Telemetry.StartOp(ctx, "reprice-cart", sb.WithOpBusinessKey(cartID))
	if err := reprice(ctx, cartID); err != nil {
		op.Fail(err)
		return err
	}
	op.End()

	c.Telemetry.Counter("carts_repriced_total", map[string]string{"tier": "gold"}).Inc()
	c.Telemetry.Gauge("queue_depth", "", nil).Set(42)
	c.Telemetry.Histogram("reprice_ms", "ms", nil, []float64{1, 5, 10, 50, 100}).Observe(12.5)
	return nil
}
```

**`StartOp` возвращает контекст, несущий операцию как родителя.** Передавайте вниз именно его: иначе вызовы, сделанные внутри, начнут собственный корень трейса, и один запрос превратится в два дерева. `sb.WithOpPeer(serviceID)` называет сервис, с которым операция говорит.

Ручки метрик пересобираются при смене идентичности, поэтому ручка, взятая один раз на всю жизнь процесса, продолжает отчитываться под живым инстансом, а не под тем, который рантайм уже снёс.

Всё, записанное до `Start`, ждёт в кольцевом буфере в памяти и уезжает, когда соединение появится. Буферы раздельные по видам сигнала — всплеск одного не может вытеснить другой; при переполнении вытесняется самое старое. Потерю телеметрии видно через `sb.WithTelemetryDropHandler` и метрику `sb_sdk_telemetry_dropped_total`.

Кроме ваших метрик клиент раз в 30 секунд сам отправляет два показателя процесса: долю одного ядра CPU и объём памяти.

### Логи

```go
func logging(c *sb.Client) {
	c.Telemetry.Logger().Info("cart repriced", "cart", "c-1", "items", 7)

	handler := c.Telemetry.Logger().Handler()
	app := slog.New(handler)
	app.Warn("slow reprice", "ms", 812)
}
```

`Logger()` — обычный `*slog.Logger`. Учить второй API логирования не нужно: возьмите `Handler()` и вставьте его в свою цепочку `slog`.

**Важно понимать, куда он пишет.** Этот handler пишет **только** в буфер телеметрии — ни в stdout, ни в какой-либо другой handler. Если вам нужны логи и в консоли, и в консоли рантайма, соберите `slog.Handler`, раздающий записи в оба, — своё и это.

Уровень по умолчанию — `Info`. Атрибуты и группы `slog` сохраняются и уезжают структурированным полем. Идентификаторы трейса и операции подтягиваются из контекста, поэтому запись, сделанная внутри обработчика, оказывается привязанной к его операции.

`sb.WithLogger(*slog.Logger)` — совсем другая ручка: она задаёт, куда SDK пишет **собственную** диагностику.

### Захват тел

Режим захвата тел запросов и ответов присылает рантайм: не захватывать (`none`), захватывать только у упавших операций (`errors`) или захватывать всё (`all`). Режим рантайма по умолчанию — `errors`. До первого снапшота SDK ничего не захватывает. Предел размера тела на направление по умолчанию 65536 байт.

**SDK тела не маскирует**: они уходят как есть, маскирует их рантайм при приёме.

## 8. Troubleshooting

| Симптом | Причина и что делать |
|---|---|
| `CodeState` при регистрации обработчика | Регистрация после `Start`. Все объявления — до него. |
| `CodeConfig` при регистрации обработчика | Клиент создан с `WithCallerOnly()`. |
| `CodeState` при публикации события | Публикация до `Start`. |
| `CodeNoLiveInstance`, хотя callee запущен | Три разные причины: (1) формы сообщений разошлись, и хеши контрактов не совпадают; (2) инстансы подняты без `WithAdvertise` или как `WithCallerOnly`; (3) у всех инстансов разомкнут размыкатель. Сверьте `c.ServiceMap()`: есть ли метод и есть ли у инстансов `CallEndpoint`. |
| `CodeAccessDenied` | Политика доступа. См. [Access Policy](./access-policy.md). |
| `CodeInvalidEventName` | Имя не подходит под `^[a-z0-9_-]+(\.[a-z0-9_-]+)*$`. В публикуемом имени подстановочные знаки недопустимы. |
| `CodeQueueFull` при публикации | Очередь публикаций на пределе: рантайм недоступен или не успевает подтверждать. Проверьте связность; при постоянно большом объёме поднимите `WithMaxPendingPublishes`. |
| `CodeTimeout` при публикации | Рантайм не подтвердил событие за `WithPublishTimeout`. Сообщение говорит, было ли событие отправлено; отправленное повторяйте только с `WithEventIdempotencyKey`. |
| Вызов падает по таймауту и не повторяется | Так и задумано. SDK повторяет только доказанные отказы до отправки; после таймаута исход неизвестен, и решение о повторе — за вызывающим. |
| Задача не срабатывает | Проверьте cron-выражение: пять полей, секунд нет. Ошибка в нём отвергается при объявлении, поэтому «тихо не срабатывает» — обычно другой сервис или отключённая возможность в политике. |
| Задача выполняется дважды | Обработчик не идемпотентен по `IdempotencyKey`. Дедупликация по `Attempt` не работает: номер меняется на каждой попытке. |
| Обработчик события не вызывается | Имя не совпадает с шаблоном, фильтр `WithFilter` не пропускает событие, подписка объявлена после `Start`, либо политика отвергла её — смотрите `OnPolicyViolation`. |
| Доставки отклоняются с `no handler for matched patterns` | Рантайм прислал доставку по шаблону, обработчика которого в этом процессе нет: разные инстансы сервиса объявляют разные подписки. |
| Один запрос виден как два дерева трейса | Потерян контекст: не передан `ctx` из `StartOp` либо не подменён `*http.Request` из `Begin`. |
| Логи через `Telemetry.Logger()` не видны в консоли | Так и задумано: этот handler пишет только в телеметрию. Для локального вывода добавьте в цепочку свой handler. |
| Клиент бесконечно переподключается | По умолчанию так и есть — предела попыток нет. Смотрите причину в `OnReconnecting`; ограничить можно через `WithReconnectAttempts`. |
| Клиент остановился и не переподключается | Терминальный отказ: учётные данные отвергнуты, сервис неизвестен, регистрация отвергнута (например, фильтр подписки), версия протокола не совпадает. Причина — в `OnDisconnected`. |

## 9. Единицы времени

Всё на проводе — `int64` **unix-миллисекунды** для моментов и `int64` **миллисекунды** для длительностей.

В Go вы пишете `time.Duration` (`WithTimeout`, `job.WithLeaseTTL`, `wf.CallOpts.Timeout`, `wf.RetryPolicy.BaseDelay`), а SDK переводит. Где поле уже число, единица стоит в имени: `OccurredAtMs`, `ScheduledAtUnixMs`, `LocalScheduledAtUnixMs`, `UnhealthySinceMs`, `InitialMs`, `MaxMs`, `LeaseTTLMs`.

Длительности workflow — тоже `time.Duration`: `wf.Control.Timeout`, `wf.Definition.Timeout`, `wf.Sleep.Duration`, `sb.WithRunTimeout`.
