## 1. Конструктор и опции

```go
func build() (*sb.Client, error) {
	return sb.New("localhost:14445", os.Getenv("ORDERS_KEY"),
		sb.WithAdvertise(os.Getenv("POD_IP"), 50051),
		sb.WithCallDefaults(sb.WithTimeout(10*time.Second)),
		sb.WithCallAttempts(3),
		sb.WithDataDir("/var/lib/orders/sb"),
		sb.WithMaxOutboxRows(50_000),
		sb.WithInboundLimits(256, 256),
		sb.WithReconnectLadder(time.Second, 5*time.Second, 30*time.Second),
	)
}
```

`sb.New` **не делает ввода-вывода**. Всё, что не так с конфигурацией, сообщается здесь же, с кодом `CodeConfig`: неверная граница не должна выглядеть как сетевое условие и бесконечно кормить лестницу переподключения.

Адрес принимается и в виде `host:port`, и в виде URL — в развёртываниях встречается и то, и другое.

**SDK не читает ни одной переменной окружения.** Откуда берутся адрес, ключ и всё остальное — решаете вы.

| Опция | По умолчанию | Что делает |
|---|---|---|
| `WithAdvertise(host, port)` | `127.0.0.1`, порт `0` | Адрес, который набирают для прямого RPC. Порт `0` просит свободный у ОС и объявляет выданный. В контейнере передавайте реальный адрес: значение объявляется как есть. |
| `WithCallerOnly()` | выключено | Только исходящий инстанс: входящий слушатель не поднимается, регистрация обработчика запрещена. Противоречит `WithAdvertise`. |
| `WithCallDefaults(opts...)` | нет | `CallOption`, применяемые к каждому вызову, который их не перекрыл. |
| `WithCallAttempts(n)` | `3` | Всего попыток одного логического вызова, считая первую: три — это один вызов и два повтора. |
| `WithFailOnPolicyViolation()` | выключено | Останавливать клиент при нарушении политики, а не только сообщать о нём. |
| `WithDataDir(dir)` | `./.servicebridge` | Каталог, где лежит база локального outbox (файл `sdk.db`). |
| `WithMaxOutboxRows(n)` | `10000` | Предел локального буфера событий; сверх него `Publish` возвращает `CodeOutboxFull`. `0` снимает предел — буфер без предела превращает долгую недоступность в заполненный диск. |
| `WithDrainBatchSize(n)` | `100` | Сколько буферизованных событий захватывает одна итерация дренажа. |
| `WithMaxInFlightEvents(n)` | `32` | Одновременно обрабатываемых входящих доставок. На пределе стрим доставок перестаёт вычитываться — это и есть backpressure. |
| `WithInboundLimits(calls, streams)` | `512` / `512` | Одновременно работающих обработчиков по всем соединениям и HTTP/2-стримов на соединение. За первой границей вызывающий получает `ResourceExhausted` — нагрузка сбрасывается, а не ставится в очередь. |
| `WithReconnectAttempts(n)` | `0` — без предела | Предел подряд идущих попыток переподключения. Сервис, сдавшийся посреди rolling restart, — это сервис, к которому придётся идти руками. |
| `WithReconnectLadder(rungs...)` | `1s, 5s, 15s, 30s, 60s` | Задержки переподключения. Последняя ступень повторяется бесконечно, каждая — с джиттером ±20 %. |
| `WithLogger(log)` | `slog.Default()` | Куда SDK пишет собственную диагностику. |

Значения по умолчанию экспортированы константами: `sb.DefaultDataDir`, `sb.DefaultMaxOutboxRows`, `sb.DefaultDrainBatchSize`, `sb.DefaultMaxInFlightEvents`, `sb.DefaultMaxConcurrentCalls`, `sb.DefaultMaxConcurrentStreams`, `sb.DefaultCallAttempts`, `sb.DefaultAdvertiseHost`.

### Что отвергается сразу

`CodeConfig` из `sb.New` получают: пустой адрес рантайма; неразбираемый bootstrap-ключ; `WithCallerOnly` вместе с `WithAdvertise`; пустой хост при не-caller-only; порт вне `0..65535`; пустой каталог данных; отрицательный предел буфера; неположительные размер пачки, предел доставок, входящие лимиты и бюджет попыток; отрицательный предел переподключений; отрицательный таймаут вызова по умолчанию; нулевой логгер; неположительная ступень лестницы.

### Типичные наборы

```go
func callerOnly(key string) (*sb.Client, error) {
	// Процесс, который только вызывает: cron-утилита, скрипт миграции, шлюз.
	return sb.New("localhost:14445", key, sb.WithCallerOnly())
}
```

```go
func inKubernetes(key string) (*sb.Client, error) {
	// Под, который обслуживает RPC. Адрес обязателен: loopback по умолчанию
	// объявится как есть, и до пода никто не дозвонится.
	return sb.New("servicebridge.svc.cluster.local:14445", key,
		sb.WithAdvertise(os.Getenv("POD_IP"), 50051),
		sb.WithDataDir("/var/lib/orders/sb"),
		sb.WithFailOnPolicyViolation(),
	)
}
```

```go
func highVolumePublisher(key string) (*sb.Client, error) {
	// Много публикаций: больше буфер и крупнее пачка дренажа.
	return sb.New("localhost:14445", key,
		sb.WithCallerOnly(),
		sb.WithMaxOutboxRows(200_000),
		sb.WithDrainBatchSize(500),
	)
}
```

## 2. Жизненный цикл: Start и Stop

```go
func lifecycle(ctx context.Context, key string) error {
	c, err := sb.New("localhost:14445", key)
	if err != nil {
		return err
	}

	// объявления: обработчики, зависимости, события, задачи, workflow
	if err := sb.Handle(c, "Ship", shipHandler); err != nil {
		return err
	}
	payment := sb.NewClient(c, "payment-svc")
	if _, err := sb.NewMethod[*paymentpb.ChargeRequest, *paymentpb.ChargeReply](payment, "Charge"); err != nil {
		return err
	}

	if err := c.Start(ctx); err != nil {
		return err
	}
	defer func() { _ = c.Stop(ctx) }()

	// ... работа ...
	return nil
}
```

### Что делает Start

В единственном порядке, который работает:

1. Запечатывает объявления — с этого момента mesh знает, что существует.
2. Открывает локальный outbox, чтобы публикации было куда durable-записаться.
3. Регистрирует всех держателей mTLS-материала, чтобы первый же лиз дошёл до каждого.
4. Отдаёт управление жизненному циклу: тот провижинит сертификат (или переиспользует кэшированный), поднимает входящий сервер, открывает управляющую сессию и только потом стартует поток реестра — адрес слушателя обязан лежать уже в самом первом кадре регистрации, иначе mesh будет звонить туда, где никто не слушает.
5. Дожидается первого снапшота — это и есть подтверждение регистрации.
6. Поднимает подписки, которым нужна зарегистрированная идентичность.

`Start` возвращается, когда инстанс зарегистрирован и маршрутизируем.

**Клиент переживает контекст, переданный в `Start`.** Его отмена отбрасывается, а значения сохраняются: контекст уровня запроса не должен уметь положить клиент. Опускать клиент — задача `Stop`.

Повторный `Start` — `CodeState`. `Start` после `Stop` — тоже.

### Что делает Stop

Освобождает все ресурсы в порядке, обратном `Start`, идемпотентен, и сообщает первый сбой, не пропуская остальные: оставленный открытым канал держал бы свои горутины переподключения до конца жизни процесса.

Обработчики видят отменённый контекст. Обработчик, игнорирующий отмену, держит `Stop` ровно столько, сколько работает.

### Мягкое завершение

```go
func serveUntilSignal(c *sb.Client) error {
	ctx := context.Background()
	if err := c.Start(ctx); err != nil {
		return err
	}

	stop := make(chan os.Signal, 1)
	signal.Notify(stop, syscall.SIGINT, syscall.SIGTERM)
	<-stop

	shutdown, cancel := context.WithTimeout(context.Background(), 30*time.Second)
	defer cancel()
	return c.Stop(shutdown)
}
```

## 3. Колбэки соединения

```go
func observe(c *sb.Client) {
	c.OnConnected(func(id sb.Identity) {
		log.Println("connected as", id.ServiceName, id.InstanceID)
	})
	c.OnReconnecting(func(attempt int, cause error) {
		log.Println("reconnecting", attempt, cause)
	})
	c.OnDraining(func(reason string) {
		log.Println("runtime is draining:", reason)
	})
	c.OnDisconnected(func(cause error) {
		log.Println("disconnected:", cause)
	})
	c.OnPolicyViolation(func(v sb.PolicyViolation) {
		log.Println("policy refused", v.Declaration, v.Value, v.Reason)
	})
}
```

| Колбэк | Когда срабатывает |
|---|---|
| `OnConnected` | Один раз на живую сессию, после приветствия рантайма. Срабатывает заново на каждой ротации сертификата. |
| `OnReconnecting` | Перед каждой попыткой восстановить потерянную сессию. |
| `OnDraining` | Рантайм объявил, что выключается. |
| `OnDisconnected` | Один раз, когда клиент перестал пытаться переподключиться. |
| `OnPolicyViolation` | На каждое объявление, отвергнутое политикой, — и из снапшота реестра, и из отказанной публикации события. |

Колбэки выполняются на собственных горутинах клиента и **не должны блокировать**. Регистрировать их можно несколько на одно событие.

## 4. Identity и ServiceMap

```go
func whoAmI(c *sb.Client) {
	id := c.Identity()
	log.Println(id.ServiceID, id.ServiceName, id.InstanceID, id.SessionID)
}
```

**`Identity` читается по требованию и никогда не кэшируется**: каждая ротация сертификата выдаёт новый `InstanceID` при том же `ServiceID`. Сохранённая в переменную копия после первой же ротации указывает на инстанс, которого уже нет.

```go
func waitForMethod(ctx context.Context, c *sb.Client, service, method string) error {
	for {
		for _, m := range c.ServiceMap().Methods {
			if m.ServiceName == service && m.Name == method {
				return nil
			}
		}
		select {
		case <-ctx.Done():
			return ctx.Err()
		case <-time.After(200 * time.Millisecond):
		}
	}
}
```

`ServiceMap` — снимок mesh на момент вызова: `Instances` (с `CallEndpoint`, `HTTPEndpoint`, `Status`, `UnhealthySinceMs`) и `Methods` (с `Type`, `ContractHash`, `Streaming`).

## 5. Входящий сервер и advertise

Входящий сервер поднимается, если клиент **не** объявлен как `WithCallerOnly`.

| Сценарий | Как настроить |
|---|---|
| Локальная разработка | Ничего: по умолчанию `127.0.0.1:0`, порт выдаёт ОС. |
| Под в Kubernetes | `sb.WithAdvertise(os.Getenv("POD_IP"), 50051)`. |
| Контейнер с проброшенным портом | Хост и порт, по которым до контейнера дозваниваются снаружи, — не те, что внутри. |
| Процесс, который только вызывает | `sb.WithCallerOnly()`. |

Что попадает в реестр: адрес для прямого RPC (`call_endpoint`), список входящих методов со схемами и хешами контрактов, публикуемые события, подписки, исходящие зависимости и — если подключён `sbhttp` — адрес HTTP-сервера с роутами.

Сверх `WithInboundLimits` вызовы **сбрасываются**, а не встают в очередь: очередь перед насыщенным пулом обработчиков превращает перегрузку в неограниченный рост памяти. Вызывающий получает `ResourceExhausted`, который на его стороне классифицируется как безусловно ретраебельный — работа не выполнялась.

## 6. Безопасность: ключ, mTLS, ротация

### Bootstrap-ключ

Строка вида `sb.<base64url>` из дашборда. Внутри — идентификатор ключа, секрет и **сертификат CA**.

CA едет внутри ключа не для удобства: первое же соединение с рантаймом оказывается привязанным к известному корню, без окна доверия при первом контакте. SDK доверяет ровно этому корню и ничему из системного хранилища.

Ключ — это секрет. Держите его в `.env` (в `.gitignore`) или в менеджере секретов, передавайте в `sb.New` явно.

### Что происходит при подключении

1. SDK генерирует свежую пару ключей P-256 и запрос на сертификат.
2. Отправляет его вместе с идентификатором ключа и секретом по каналу, привязанному к CA из bootstrap-ключа.
3. Рантайм возвращает листовой сертификат с SPIFFE-идентичностью инстанса.
4. Дальше всё общение идёт по mTLS этим сертификатом.

Один и тот же ключ можно использовать в нескольких процессах: каждый получит свою идентичность инстанса при общем `ServiceID`.

### Ротация

Сертификат обновляется **заранее**, а не по истечении: примерно за 30 минут до конца срока, со случайным разбросом до 5 минут, чтобы весь флот не пошёл обновляться одновременно. Обновление идёт по живому mTLS-каналу, а не через первичный провижининг.

Ротация даёт **новый `InstanceID` при том же `ServiceID`**, и новая сессия должна быть принята рантаймом раньше, чем закрывается старая, — благодаря перекрытию долгоживущие инстансы не теряют трафик в момент замены.

Неудачная ротация ничего не меняет местами: клиент остаётся на текущем сертификате и повторяет попытку по лестнице.

Кэш лиза живёт **только в памяти**. Единственный файл, который SDK вообще пишет, — база локального outbox.

Скомпрометированный ключ отзывается в рантайме; после этого сервису нужен новый ключ и перезапуск с ним.

## 7. Телеметрия

Каждый RPC, событие, задача, шаг workflow и HTTP-запрос уже создают операцию и протягивают трассировку между хопами. `c.Telemetry` добавляет ваши собственные.

```go
func instrumented(ctx context.Context, c *sb.Client, cartID string) error {
	ctx, op := c.Telemetry.StartOp(ctx, "reprice-cart", sb.WithOpBusinessKey(cartID))
	if err := reprice(ctx, cartID); err != nil {
		op.Fail(err)
		return err
	}
	op.End()

	c.Telemetry.Counter("carts_repriced_total", map[string]string{"tier": "gold"}).Inc()
	c.Telemetry.Gauge("queue_depth", "", nil).Set(42)
	c.Telemetry.Histogram("reprice_ms", "ms", nil, []float64{1, 5, 10, 50, 100}).Observe(12.5)
	return nil
}
```

**`StartOp` возвращает контекст, несущий операцию как родителя.** Передавайте вниз именно его: иначе вызовы, сделанные внутри, начнут собственный корень трейса, и один запрос превратится в два дерева. `sb.WithOpPeer(serviceID)` называет сервис, с которым операция говорит.

Ручки метрик пересобираются при смене идентичности, поэтому ручка, взятая один раз на всю жизнь процесса, продолжает отчитываться под живым инстансом, а не под тем, который рантайм уже снёс.

Всё, записанное до `Start`, ждёт в кольцевом буфере в памяти и уезжает, когда соединение появится. Буферы раздельные по видам сигнала — всплеск одного не может вытеснить другой; при переполнении вытесняется самое старое.

Кроме ваших метрик клиент раз в 30 секунд сам отправляет два показателя процесса: долю одного ядра CPU и объём памяти.

### Логи

```go
func logging(c *sb.Client) {
	c.Telemetry.Logger().Info("cart repriced", "cart", "c-1", "items", 7)

	handler := c.Telemetry.Logger().Handler()
	app := slog.New(handler)
	app.Warn("slow reprice", "ms", 812)
}
```

`Logger()` — обычный `*slog.Logger`. Учить второй API логирования не нужно: возьмите `Handler()` и вставьте его в свою цепочку `slog`.

**Важно понимать, куда он пишет.** Этот handler пишет **только** в буфер телеметрии — ни в stdout, ни в какой-либо другой handler. Если вам нужны логи и в консоли, и в консоли рантайма, соберите `slog.Handler`, раздающий записи в оба, — своё и это.

Уровень по умолчанию — `Info`. Атрибуты и группы `slog` сохраняются и уезжают структурированным полем. Идентификаторы трейса и операции подтягиваются из контекста, поэтому запись, сделанная внутри обработчика, оказывается привязанной к его операции.

`sb.WithLogger(*slog.Logger)` — совсем другая ручка: она задаёт, куда SDK пишет **собственную** диагностику.

### Захват тел

Захват тел запросов и ответов выключен по умолчанию и включается режимом, который присылает рантайм: не захватывать, захватывать только у упавших операций или захватывать всё. Локально режим можно только **сузить**, но не расширить: настройку, которую разрешил оператор, клиент не переигрывает. Предел размера тела на направление по умолчанию 65536 байт.

## 8. Troubleshooting

| Симптом | Причина и что делать |
|---|---|
| `CodeState` при регистрации обработчика | Регистрация после `Start`. Все объявления — до него. |
| `CodeConfig` при регистрации обработчика | Клиент создан с `WithCallerOnly()`. |
| `CodeState` при публикации события | Публикация до `Start` — локального буфера ещё нет. |
| `CodeNoLiveInstance`, хотя callee запущен | Три разные причины: (1) формы сообщений разошлись, и хеши контрактов не совпадают; (2) инстансы подняты без `WithAdvertise` или как `WithCallerOnly`; (3) все инстансы отсечены размыкателем или помечены нездоровыми. Сверьте `c.ServiceMap()`: есть ли метод и есть ли у инстансов `CallEndpoint`. |
| `CodeAccessDenied` | Политика доступа. См. [Access Policy](./access-policy.md). |
| `CodeInvalidEventName` | Имя не подходит под `^[a-z0-9_-]+(\.[a-z0-9_-]+)*$`. В публикуемом имени подстановочные знаки недопустимы. |
| `CodeOutboxFull` | Буфер на пределе: рантайм недоступен дольше, чем вмещает буфер. Проверьте связность; при постоянно большом объёме поднимите `WithMaxOutboxRows`. |
| Вызов падает по таймауту и не повторяется | Так и задумано. `DeadlineExceeded` повторяется **только** с `WithIdempotencyKey`: дедлайн истёк у вызывающего и ничего не говорит про callee. |
| Задача не срабатывает | Проверьте cron-выражение: пять полей, секунд нет. Ошибка в нём отвергается при объявлении, поэтому «тихо не срабатывает» — обычно другой сервис или отключённая возможность в политике. |
| Задача выполняется дважды | Обработчик не идемпотентен по `IdempotencyKey`. Дедупликация по `Attempt` не работает: номер меняется на каждой попытке. |
| Обработчик события не вызывается | Имя не совпадает, либо подписка объявлена после `Start`, либо политика отвергла её — смотрите `OnPolicyViolation`. |
| Один запрос виден как два дерева трейса | Потерян контекст: не передан `ctx` из `StartOp` либо не подменён `*http.Request` из `Begin`. |
| Логи через `Telemetry.Logger()` не видны в консоли | Так и задумано: этот handler пишет только в телеметрию. Для локального вывода добавьте в цепочку свой handler. |
| Клиент бесконечно переподключается | По умолчанию так и есть — предела попыток нет. Смотрите причину в `OnReconnecting`; ограничить можно через `WithReconnectAttempts`. |
| Не открывается локальный буфер после обновления SDK | Схема файла изменилась. Остановите сервис и удалите файл `sdk.db` в каталоге данных, потеряв то, что в нём ещё лежало. |

## 9. Единицы времени

Всё на проводе — `int64` **unix-миллисекунды** для моментов и `int64` **миллисекунды** для длительностей.

В Go вы пишете `time.Duration` (`WithTimeout`, `job.WithLeaseTTL`, `wf.CallOpts.Timeout`, `wf.RetryPolicy.BaseDelay`), а SDK переводит. Где поле уже число, единица стоит в имени: `OccurredAtMs`, `ScheduledAtUnixMs`, `LocalScheduledAtUnixMs`, `UnhealthySinceMs`, `InitialMs`, `MaxMs`, `LeaseTTLMs`.

Секунды встречаются ровно в пяти местах и всегда написаны в имени — это единица контракта workflow, а не опечатка:

- `wf.Control.TimeoutSec`
- `wf.Definition.TimeoutSec`
- `wf.Sleep.DurationSec`
- `wf.StartOpts.TimeoutSec`
- `sb.WithRunTimeoutSec`
