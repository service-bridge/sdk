# events

## Зона ответственности

Durable-события Go SDK: публикация (запись в локальный outbox либо прямая отправка в режиме «без ожидания»), дренаж буфера в рантайм через `Events.Publish`, подписка через двунаправленный стрим `Events.Subscribe` с FIFO по ключу партиции и реальным ограничением конкурентности.

Не делает: не хранит события (это `internal/outbox`), не открывает соединение и не держит mTLS-креды (это `internal/connection`), не решает, когда переоткрывать стрим (это `internal/stream`), не объявляет подписки рантайму (это `internal/registry`), не эмитит операции телеметрии — `EVENT.PUBLISH` и `EVENT.DELIVER` принадлежат рантайму по матрице владения (ADR-0001); отсюда берётся только контекст трассировки.

## Публичный контракт

Публичный для других пакетов SDK; наружу через корневой `servicebridge` не реэкспортируется.

## Архитектурные решения и почему

**Публикация возвращается быстро, потому что это локальная вставка.** Сеть в этот путь не входит вообще: недоступный рантайм не имеет права ни замедлить публикацию, ни провалить её. Тест `TestPublishReturnsFast` фиксирует 50 публикаций против транспорта, который никогда не отвечает.

**Проверка лимита и вставка — одна транзакция.** Иначе конкурентные публикации обе видят счётчик ниже предела и обе проскакивают. Механика — в `internal/outbox`.

**JSON-зеркало пишется всегда.** Рантайм зовёт workflow-хук после каждого принятого события — включая режим «без ожидания» — и читает `payload_json`, чтобы считать JSON-path фильтры `wait_event`, не декодируя protobuf (ADR-0002, `runtime/internal/events/ingest.go`). Пропуск зеркала тихо ломает ожидание события в workflow.

**Транспортный отказ не расходует бюджет попыток.** Лестница `1s · 5s · 30s · 2m · 10m` — ограничитель темпа, а не бюджет: последняя ступень повторяется бесконечно. Бюджет из пяти попыток означал бы, что после 2 минут 40 секунд недоступности рантайма все буферизованные события помечаются проваленными навсегда — при том что публикация уже вернула успех и пообещала durability. Терминальны только осмысленные вердикты по конкретному конверту: невалидное имя и запрет политикой. Тест `TestRuntimeDowntimeNeverBuriesBufferedEvents` прогоняет больше часа модельного простоя.

**Запрет политикой доходит до владельца.** Публикация вернулась задолго до отправки, выбросить ошибку вызывающему уже некуда, поэтому отказ едет и в лог уровня `Warn`, и в колбэк `OnPolicyViolation`.

**Отсутствие вердикта — это тот же транспортный случай.** `PUBLISH_STATUS_UNSPECIFIED` и молчание про конкретный `event_id` означают, что рантайм ничего про событие не сказал. Такое событие повторяется, а не хоронится.

**Пачка — одна транзакция, подготовленные выражения переиспользуются.** Построчная компиляция SQL и транзакция на строку превращают сто событий в сто записей в журнал вместо одной.

**Простой считается по ближайшей отложенной строке.** Цикл спит ровно до `MIN(next_attempt_at_ms)`, а не фиксированный интервал; при пустом буфере таймера нет вообще. Пробуждение — буферизованный канал на одну позицию: сигнал, пришедший во время итерации, доживает до следующего ожидания и не теряется.

**Идентичность читается на каждое открытие стрима.** `instance_id` меняется каждой ротацией сертификата. Копия, снятая при создании подписчика, после первой же ротации отправляет рантайму мёртвый идентификатор — в Node на этом сгорели в трёх местах.

**Переподключение — общий супервизор.** `internal/stream` уже владеет поколениями стрима, защитой от кадров мёртвого поколения и лестницей. Свой автомат означал бы второй набор тех же багов.

**FIFO по ключу партиции обеспечивается локально.** Рантайм гарантирует не более одного «в полёте» на пару (потребитель, ключ), но доставки приходят асинхронно, и два обработчика успевают пойти внахлёст. События с одинаковым непустым ключом выстраиваются в цепочку промисов на каналах; пустой ключ идёт параллельно, потому что требования порядка у него нет.

**Ограничение конкурентности — настоящий backpressure.** Слот берётся на горутине супервизора, поэтому по достижении предела стрим просто перестаёт вычитываться и рантайм это чувствует. В Node значение только объявлялось серверу в кадре инициализации и больше нигде не использовалось — ни на клиенте, ни в рантайме, — то есть документированная опция не делала ничего. Тест `TestMaxInFlightStopsReadingTheStream` смотрит на счётчик `Recv`.

**Нет обработчика — подтверждаем.** Маршрутизация серверная (ADR-0002); неизвестное имя — не локальная ошибка, которую стоит повторять.

**Шаблон сопоставляется и локально.** Рантайм маршрутизирует по шаблону подписки, но доставка приходит с конкретным именем, которое публикатор указал при отправке. Поиск обработчика только по точному имени нашёл бы под ним пусто, и доставка подтвердилась бы, не выполнив ничего — подписка на семейство событий выглядела бы работающей, ничего не делая. Семантика повторяет рантаймовый матчер: `*` — ровно один сегмент, `#` — ноль или более. Требование хотя бы одного сегмента у `#` оставило бы без обработчика доставку, которую рантайм сюда направил.

**Паника обработчика — отклонение, а не падение процесса.** Паника на горутине доставки убила бы весь процесс и оставила доставку без ответа. Она превращается в `nack` с причиной.

**Запись в стрим сериализована.** gRPC запрещает конкурентный `Send` на одном стриме, а подтверждения приходят с многих горутин обработчиков.

**Телеметрия отсюда не пишется.** `EVENT.PUBLISH` и `EVENT.DELIVER` — операции рантайма (ADR-0001). SDK берёт из `internal/telemetry` только формат `X-SB-Trace`: публикация кладёт заголовок в конверт, доставка разворачивает его в контекст обработчика, чтобы вложенные вызовы попали в то же дерево.

**Дженерики только там, где они что-то дают.** `Subscribe[T]` обязан завести значение типа `T` и декодировать в него, поэтому он параметризован. Публикация отдаёт payload кодеку как `any` — параметр типа там не добавил бы ни одной проверки, только шум в сигнатуре.

## Зависимости

Опирается на:
- `internal/outbox` — локальное хранилище буфера;
- `internal/stream` — супервизор стрима подписки и лестница повторов;
- `internal/telemetry` — `FromContext`, `WithTraceContext`, `FormatHeader`, `ParseHeader`;
- `internal/pb/servicebridge/v1` — контракт `Events`;
- `github.com/google/uuid` — UUIDv7 для идентификаторов событий.

На него опираются: корневой пакет `servicebridge` (сборка графа зависимостей клиента: транспорт `Events`, кодек из слоя сериализации, идентичность из `internal/connection`, объявления подписок через `internal/registry`).
