# rpc

## Зона ответственности

Пакет держит обе стороны Direct RPC. Этот README описывает **входящую** сторону: mTLS-сервер `servicebridge.v1.Call`, который слушает инстанс SDK (`server.go`), проверку приёма вызывающего (`acceptance.go`) и индекс хендлеров (`dispatch.go`). В рантайме этот сервис никто не реализует — его дёргают и другие SDK напрямую, и рантайм в режиме прокси.

Не делает: не выбирает целевой инстанс, не ретраит, не сериализует бизнес-типы (хендлер получает и возвращает сырые байты), не эмитит операции телеметрии.

Исходящая сторона (`client.go`, `direct.go`, `proxy.go`, `lb.go`, `breaker.go`, `retry.go`) описывается отдельным разделом её владельцем.

## Архитектурные решения и почему

**Ошибка хендлера едет телом, транспортный сбой — статусом.** Это не косметика, а основа решения о ретрае у вызывающего: `ResourceExhausted` или `Unavailable` означают «попробуй другой инстанс», а `error_code = INTERNAL` при статусе `OK` означает «тебе ответили, повтор ничего не изменит». Слитые вместе, они превращают каждую бизнес-ошибку в шторм ретраев. Единственное исключение — сбой декодирования: это ошибка вызывающего, и она едет `InvalidArgument`.

**Сервер не эмитит операцию телеметрии.** На один логический вызов приходится ровно одна строка, и владеет ею вызывающий SDK (ADR-0001). Строка со стороны callee удвоила бы каждый вызов в дереве трассировки. Хендлер работает в контексте трассировки вызывающего, поэтому его вложенные операции цепляются прямо к строке вызывающего. Тест `TestServerEmitsNoTelemetryOperation` проверяет это через `parent_op_id` вложенной операции: серверная строка была бы видна как лишнее звено между ними.

**Проверка приёма идёт до занятия слота.** Иначе неавторизованный вызывающий занимает место, за которое конкурируют легитимные, — то есть отказ в обслуживании стоит атакующему одного отвергнутого вызова.

**Переполнение — сброс, а не очередь.** `semaphore.TryAcquire` не ждёт: при исчерпании слотов приходит `ResourceExhausted`. Очередь перед насыщенным пулом хендлеров превращает перегрузку в неограниченный рост памяти и отвечает всем поздно вместо того, чтобы ответить большинству вовремя. В Node у входящих RPC предела не было ни на каком уровне: десять тысяч одновременных вызовов означали десять тысяч живых хендлеров и OOM вместо честного отказа. Границ две: `MaxConcurrentCalls` — глобальный предел хендлеров, `grpc.MaxConcurrentStreams` — предел стримов на соединение.

**Границы валидируются при создании.** Неположительная граница — ошибка `ErrServerConfig` сразу, а не подстановка умолчания. Дробного случая в Go нет: тип `int` его не выражает. Умолчания берутся явным вызовом `DefaultServerLimits()`, потому что граница, которая подставилась молча, — это граница, о которой никто не знает. `ErrServerConfig` намеренно отдельный sentinel: в Node ошибка конфигурации классифицировалась как сетевая и уходила в бесконечный реконнект.

**Личность пира опознаётся положительно.** Лист с URI SAN обязан дать SPIFFE-идентичность; если ни один URI не разбирается — отказ. В Node фолбэк разрешал любого пира, чей SAN не удалось разобрать, то есть ошибка парсинга открывала дверь. Лист без URI SAN — это только прокси рантайма и только если его CN об этом говорит: рантайм никогда не выдаёт сервису лист без SAN, поэтому две формы не перепутать. CN здесь можно доверять ровно потому, что цепочка уже проверена против закреплённого CA.

**Разбор SPIFFE не дублируется.** Берётся `connection.ParseSPIFFE` — вторая реализация разошлась бы с первой ровно в тот день, когда изменится формат.

**Разбор `x_sb_trace` идёт через `telemetry.ParseHeader`.** Единственный парсер в SDK (ADR-0006 §7). Значение приходит двумя путями: рантайм на прокси-пути ставит gRPC-метаданные, прямой вызывающий заполняет поле тела; метаданные выигрывают, когда есть оба. Битое значение — не ошибка, а отсутствие пригодного трейса, поэтому начинается новое дерево (ADR-0006 §6).

**Сертификат меняется под живым слушателем.** `GetConfigForClient` читает текущий `material` на каждом handshake, поэтому ротация не пересоздаёт сокет. Адрес уже лежит в кеше реестра у каждого пира — перебиндивание направило бы весь меш на сокет, которого никто не слушает. Слушатель поднимается до публикации первых учётных данных (так устроен `connection.Lifecycle`: адрес нужен уже в первом `RegisterRequest`), и в это окно handshake честно отвергается вместо того, чтобы обслуживать без проверки.

**Поиск хендлера — одно обращение к map.** Индекс заменяется целиком при регистрации и читается через атомарный указатель, так что входящий вызов не берёт ни одного лока. В Node это был линейный перебор дважды на каждый входящий вызов.

**Регистрация закрывается стартом.** Объявленный набор хендлеров уезжает рантайму в первом `RegisterRequest`; хендлер, добавленный позже, существует только локально, и меш в него никогда не маршрутизирует. `Seal` делает это громкой ошибкой вместо тихой.

**Паника пользовательского хендлера стоит своего вызова и больше ничего.** Она перехватывается, логируется со стеком и возвращается вызывающему телом как `INTERNAL`; процесс продолжает обслуживать остальных.

**Backpressure — это блокирующий `Send`, но остановка — это `ctx`.** `Send` сам ждёт на HTTP/2 flow control, однако вызывающий, который ушёл, не разблокирует ничего: производство прекращает `ctx.Done()`, а `Sender` возвращает ошибку и после отмены, чтобы хендлер, игнорирующий `ctx`, всё равно остановился. В Node отменённый стрим оставлял генератор работать до конца. Записи в один стрим сериализуются: gRPC запрещает конкурентный `Send`, а хендлер волен разложить производство по горутинам.

## Зависимости

Опирается на:
- `internal/connection` — `ParseSPIFFE` и `Identity` для опознания пира, `Credentials` и `Lease` для mTLS-материала;
- `internal/telemetry` — `ParseHeader`, `MetadataKey`, `WithTraceContext`;
- `internal/pb/servicebridge/v1` — `Call`, `CallRequest`, `CallResponse`, `StreamChunk`, `PolicyEvaluation`, `PolicyRule`;
- `golang.org/x/sync/semaphore` — предел одновременно работающих хендлеров;
- `google.golang.org/grpc` — сервер, mTLS-креды, статусы, метаданные, `peer`.

Опираются на него:
- `internal/connection` — через интерфейсы `InboundServer` и `CredentialConsumer` (зависимость объявлена у потребителя, обратного импорта нет);
- слой реестра — берёт `Dispatcher.Methods()` для декларации входящих методов и отдаёт `registry.Cache` как `AcceptancePolicySource`;
- публичный API SDK — регистрирует хендлеры и оборачивает сериализацию, поднимая `ErrDecode` при сбое разбора.
