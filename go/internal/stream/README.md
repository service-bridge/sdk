# internal/stream

## Зона ответственности

Один конечный автомат жизненного цикла gRPC-стрима — открыть, читать, пережить обрыв, подождать на лестнице, открыть снова — и лестница задержек, на которой он ждёт. Его используют все долгоживущие подписки SDK: реестр, события, задачи, workflow, телеметрия.

Модуль не знает ни одного домена: он не разбирает сообщения, не решает, что с ними делать, и не владеет соединением. Всё доменное приходит через `Config`.

Управляющая сессия (`internal/connection`) сознательно **не** использует супервизор — только `Backoff`. Причина в разделе «Архитектурные решения».

## Публичный контракт

| Имя | Тип | По умолчанию | Что делает |
|-----|-----|--------------|------------|
| `Receiver[M]` | interface | — | `Recv() (M, error)` — минимум, который супервизор требует от стрима. Любой серверный или двунаправленный стрим gRPC ему удовлетворяет. |
| `Config[M, S].Name` | `string` | — | Имя стрима в логах. |
| `Config[M, S].Open` | `func(ctx) (S, error)` | — | Открывает свежий стрим, привязанный к `ctx`. Отмена `ctx` обязана разблокировать `Recv`. Ошибка — нормальный обрыв, а не сбой: нет идентичности, рантайм недоступен, канал снесён ротацией. Супервизор уходит на лестницу. |
| `Config[M, S].OnData` | `func(ctx, M, S)` | — | Кадр текущего стрима вместе с самим стримом, чтобы двунаправленный обработчик мог ответить в тот же вызов. Выполняется на горутине супервизора: блокирующий обработчик блокирует весь жизненный цикл. |
| `Config[M, S].OnError` | `func(error)` | nil | Уведомление об обрыве. Решение о переподключении принимает супервизор. Чистое закрытие ошибкой не считается и сюда не приходит. |
| `Config[M, S].OnBackoff` | `func(int, time.Duration)` | nil | Выбранная задержка перед следующим открытием. |
| `Config[M, S].Backoff` | `Backoff` | `NewBackoff()` | Лестница переподключения. |
| `Config[M, S].Logger` | `*slog.Logger` | `slog.Default()` | |
| `NewSupervisor[M, S]` | `(Config) (*Supervisor, error)` | — | `ErrInvalidConfig`, если не заданы `Open` или `OnData`. |
| `Supervisor.Start` | `(ctx) error` | — | Запускает цикл. Повторный вызов — `ErrAlreadyStarted`. |
| `Supervisor.Stop` | `()` | — | Останавливает цикл и дожидается завершения горутины. Идемпотентен. |
| `Supervisor.Restart` | `()` | — | Рвёт текущий стрим, чтобы следующая итерация открыла новый. Нужен, когда сменилась идентичность после ротации сертификата и стрим надо переоткрыть с новой. |
| `Supervisor.Current` | `() (S, bool)` | — | Текущий стрим, если он открыт. |
| `NewBackoff` | `(...BackoffOption) Backoff` | лестница `1s, 5s, 15s, 30s, 60s`, джиттер 0.2 | |
| `WithLadder` / `WithJitterRatio` / `WithRandom` | `BackoffOption` | — | Ступени, доля джиттера, источник случайности (для детерминированных тестов). |
| `Backoff.Delay` | `(attempt int) time.Duration` | — | Задержка для попытки, считая с нуля. Насыщается на последней ступени. |
| `Backoff.Rungs` | `() []time.Duration` | — | Копия ступеней. |

## Приватный контракт

| Имя | Тип | Что делает |
|-----|-----|------------|
| `streamEvent[M]` | struct | Кадр или обрыв, помеченные поколением стрима. |
| `outcome` | int | Чем закончилась итерация: чистое закрытие, ошибка, отмена. Различие определяет, сбрасывать ли счётчик попыток. |
| `Supervisor.run` | method | Цикл: открыть, обслужить, подождать. |
| `Supervisor.serve` | method | Одно поколение стрима от открытия до обрыва. |
| `Supervisor.pump` | method | Читает `Recv` в канал, помечая кадры поколением. |
| `Supervisor.wait` | method | Ожидание на лестнице; возвращает false при отмене. |
| `Supervisor.setCurrent` / `clearCurrent` | method | Публикация текущего стрима под мьютексом. |

## Архитектурные решения и почему

**Три инварианта, ради которых модуль существует.** В Node SDK этот автомат написан пять раз в четырёх формах, и копии разошлись. Здесь он один, и каждый инвариант закреплён тестом.

*Счётчик попыток сбрасывается по прогрессу, а не по завершению стрима.* Прогресс — это полученный кадр. Две копии в Node сбрасывали счётчик на любом завершении, включая чистое закрытие; рантайм закрывает стрим штатно при перезагрузке настроек, и подписчик переподключался раз в секунду вечно, никогда не поднимаясь по лестнице. Самообстрел рантайма выглядел как нормальная работа.

*События мёртвого стрима игнорируются.* Каждый кадр и каждый обрыв помечены поколением; событие из прошлого поколения отбрасывается. В Node у одной копии guard'а не было: запоздалое завершение мёртвого стрима обнуляло ссылку на живой, тот становился неотменяемым, а рантайм отвергал повторную привязку — вечный цикл переподключений при живом стриме, в который продолжали идти доставки.

*Ошибка открытия — это обрыв, а не паника.* Нет идентичности, рантайм недоступен, канал снесён ротацией — всё это нормальные состояния, и путь у них один: на лестницу.

**Почему `OnData` выполняется на горутине супервизора.** Так порядок кадров сохраняется без внешней синхронизации, а обратная запись в двунаправленный стрим безопасна. Цена — блокирующий обработчик останавливает жизненный цикл; это записано в контракте, и доменные подписчики отдают тяжёлую работу своим воркерам.

**Почему управляющая сессия не использует супервизор.** Супервизор владеет одним поколением стрима и рвёт старое до открытия нового. Ротация сертификата требует обратного: новая сессия должна дожить до `Welcome`, и только потом закрывается старая — иначе на время дозвона сессия теряется. `internal/connection` берёт отсюда только `Backoff`.

**Джиттер обязателен, а не косметика.** Без него тысяча инстансов после перезапуска рантайма пойдёт переподключаться синхронно. Источник случайности инъектируется, чтобы тесты лестницы были детерминированными.

## Зависимости

Опирается на: стандартную библиотеку (`context`, `log/slog`, `math/rand`, `sync`, `time`). Ни gRPC, ни pb-стабов, ни доменных пакетов — `Receiver[M]` абстрагирует стрим.

На него опираются: `internal/registry` (watch), `internal/events` (подписка), `internal/job` (подписка), `internal/telemetry` (транспорт), `internal/workflow` (подписка). `internal/connection` использует только `Backoff`.
