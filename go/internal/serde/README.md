# serde

## Зона ответственности

Превращение сообщения в то, что уезжает на провод: канонический protobuf, его JSON-зеркало, JSON Schema и contract hash. Всё, что знает про форму пользовательских типов, живёт здесь — остальные домены получают уже готовые байты.

Не делает: не ходит в сеть, не знает про RPC, события и workflow, не хранит реестр схем (это `internal/registry`), не парсит `.proto`-файлы — схема берётся из сгенерированных типов.

## Публичный контракт

Пакет внутренний: «публичный» здесь значит «доступный другим пакетам SDK».

### Кодек

| Имя | Тип | По умолчанию | Что делает |
|-----|-----|--------------|------------|
| `Payload` | структура | — | Три поля одного сообщения: `Proto` (каноническое кодирование), `JSON` (зеркало для JSON-path фильтров `wait_event`, ADR-0002), `ContractHash`. |
| `Encode(payload any)` | `(Payload, error)` | — | Protobuf-сообщение → все три формы. Всё остальное — payload без схемы: обе формы равны его JSON-кодированию, contract hash пустой. |
| `Decode(payload []byte, out any)` | `error` | — | Заполняет `out` из канонического кодирования. Принимает сообщение, указатель на сообщение (типовой параметр приходит nil-ом) и `*[]byte` для сырой подписки. |
| `New[T](template T)` | `T` | — | Пустое сообщение того же типа. Шаблон может быть типизированным `nil` — так тип-параметр доезжает сюда без значения. |
| `DescriptorOf[T](template T)` | `protoreflect.MessageDescriptor` | — | Дескриптор типа с типизированного `nil`, чтобы дженерик узнал свой контракт без экземпляра. |
| `ErrNotProto` | `error` | — | Значение не protobuf там, где операция параметризована сгенерированным типом. Ошибка программиста, не рантайма. |

### Contract hash

| Имя | Тип | По умолчанию | Что делает |
|-----|-----|--------------|------------|
| `HashPrefix` | `const string` | `"v2"` | Версия алгоритма в самом значении: хеши разных версий не совпадают по построению. |
| `ContractHash(in, out)` | `string` | — | `"v2:" + hex(sha256(canon(in) + ":" + canon(out)))`. Идентичность пары «запрос — ответ». |
| `EventContractHash(md)` | `string` | — | То же для события: у него нет ответа, поэтому вторую половину занимает `google.protobuf.Empty` — форма односторонего метода вместо второго правила хеширования. |
| `Canonical(md)` | `[]byte` | — | Канонический JSON-дескриптор, который идёт в хеш: `{"f":[…],"o":[…],"r":{…}}`. Ключи отсортированы, пробелов нет. |

Что попадает в канонический дескриптор — только то, что определяет wire-совместимость: номера полей, кардинальность, типы. Имена полей исключены сознательно: переименование поля wire-совместимо, и хеш по именам ломал бы маршрутизацию на безвредном рефакторинге.

| Ключ | Что в нём |
|-----|-----|
| `f` | Поля, отсортированы по номеру: `n` номер, `c` кардинальность (`opt`/`rep`/`map`/`req`), `t` тип (`m:`/`e:` + полное имя для сообщений и перечислений), `k` тип ключа только у `map`. |
| `o` | Группы oneof `{"f":[номера]}`, номера внутри группы отсортированы, группы — по первому номеру. Нет oneof → ключ опускается. |
| `r` | Плоский справочник транзитивно упомянутых типов по полному имени с ведущей точкой. Сообщение → `{"f":…,"o":…}`, перечисление → `{"e":[номера, алиасы схлопнуты]}`. Цикл разрешается по имени. Пустой → ключ опускается. |

Синтетические map-entry типы в `r` не попадают: map выражен прямо в поле. Пустой хеш валиден (хендлер без схемы) и совпадает только с пустым.

Эталон один на все языковые SDK — `contract-hash-vectors.json` в корне репозитория. Тест читает именно его, а не копию в `testdata`: копия разошлась бы ровно тогда, когда общий файл меняется, и расхождение с Node всплыло бы только на живом вызове. У вектора есть `kind`: `rpc` — пара «запрос — ответ», `event` — односторонняя идентичность, где `canonicalOutput` всегда `{"f":[]}` (канонический вид `google.protobuf.Empty`), а названный в векторе output проверяет, что он в хеш не попадает. Дескрипторы к proto-векторам лежат в `testdata/desc/<имя вектора>.binpb` — `protoc --descriptor_set_out` по фикстуре из `sdk/node/src/serde/testdata/`.

### JSON Schema

| Имя | Тип | По умолчанию | Что делает |
|-----|-----|--------------|------------|
| `JSONSchema(md)` | `[]byte` | — | Схема JSON-зеркала сообщения — то, что рантайм кладёт в `input_schema_json` и рисует консоль. |

Описывает вывод `protojson`, а не Go-структуру: 64-битные целые там строки, перечисления — имена значений. Схема, утверждающая обратное, не сошлась бы с `payload_json`, по которому рантайм считает фильтры `wait_event`.

## Приватный контракт

| Имя | Тип | По умолчанию | Что делает |
|-----|-----|--------------|------------|
| `shape(md, refs)` | функция | — | Одно сообщение в канонический вид, попутно наполняя справочник `refs`. |
| `oneofs(md)` | функция | — | Группы oneof в каноническом порядке. Синтетические группы proto3 `optional` пропускаются — они не oneof на проводе. |
| `field(fd, refs)` | функция | — | Одно поле: номер, кардинальность, тип, тип ключа у map. |
| `typeRef(fd, refs)` | функция | — | Имя типа поля; для сообщений и перечислений заодно регистрирует его в справочнике. |
| `enumNumbers(ed)` | функция | — | Отсортированные номера значений перечисления с схлопнутыми алиасами. |
| `encode(v)` | функция | — | Канонический JSON: отсортированные ключи, без пробелов, без экранирования HTML. |
| `unmarshal(payload, msg)` | функция | — | Разбор канонического кодирования в готовое сообщение. |
| `objectSchema` / `fieldSchema` / `scalarSchema` | функции | — | Рекурсивная сборка JSON Schema; `open` рвёт цикл по типу. |

## Архитектурные решения и почему

**Схема из сгенерированных типов, а не из `.proto`-файла.** Node читает дескриптор из файла, на который указывает пользователь, и ошибка конфигурации вылезает первым вызовом в проде. В Go тип-параметр несёт дескриптор с собой: несовпадение контракта — ошибка компиляции, а рядом с бинарём нечего класть.

**Хеш по номерам и типам, а не по дескриптору библиотеки.** Первая версия хешировала JSON-дескриптор protobufjs — воспроизвести его в Go значило бы написать хрупкий эмулятор чужой библиотеки. Язык-нейтральное описание считается одинаково из `protoreflect` и из protobufjs, и общий файл векторов это фиксирует.

**Пустой contract hash — валидное значение, а не ошибка.** Payload workflow-графа по построению JSON-дерево без схемы; рантайм хранит его непрозрачно. Пустой хеш совпадает только с пустым, поэтому маршрутизация по хешу для таких вызовов вырождается, а не ломается.

**JSON-зеркало считается всегда, а не по требованию.** Рантайм считает по нему JSON-path фильтры `wait_event`; вычислять его лениво значило бы решать на публикации, понадобится ли оно потребителю, которого публикующий не знает.

## Зависимости

Опирается на `google.golang.org/protobuf` (`proto`, `protoreflect`, `emptypb`) и stdlib. Внутри SDK ни от чего не зависит — это лист графа.

Потребители: `internal/rpc` (кодирование вызовов и contract hash для маршрутизации), `internal/events` (payload и JSON-зеркало), `internal/workflow` (payload шагов), `internal/job`, корневой `generic.go` (`DefineEvent`, `Handle`, `NewMethod`).
