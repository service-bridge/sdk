# utils

## Зона ответственности

Доменно-нейтральные функции без состояния и без I/O, общие для нескольких доменов SDK. Project-override к user-level запрету на `utils` (см. корневой `CLAUDE.md`). Сюда попадает только то, что не привязано ни к одному домену и не держит ресурсов. Если функция начинает трогать `Repo`/`Pool`/соединения/таймеры или знает про конкретный домен — она переезжает в свой домен, а не остаётся здесь.

Сейчас здесь живут два примитива:

- расчёт reconnect-backoff — общий для подписчиков events / job / workflow и для `TelemetryTransport`, которые переоткрывают долгоживущий gRPC-стрим после разрыва;
- счётный семафор с ограниченной очередью — общий для входящего RPC-сервера (`rpc/server.ts`) и подписчиков, которым нужно ограничить число одновременно исполняемых хендлеров.

## Публичный контракт

| Имя | Тип | По умолчанию | Что делает |
|-----|-----|--------------|------------|
| `RECONNECT_LADDER_MS` | `readonly number[]` | `[1000, 5000, 15000, 30000, 60000]` | Общая лестница backoff-задержек реконнекта (мс). Индексируется номером попытки, насыщается на последней ступени. |
| `reconnectDelay(attempt, opts?)` | `(number, ReconnectDelayOptions?) => number` | — | Возвращает задержку для попытки `attempt` (zero-based): берёт ступень лестницы (с клампом в границы) и добавляет ограниченный джиттер против thundering-herd. |
| `ReconnectDelayOptions` | interface | — | `{ ladder?, jitterRatio?, random? }` |
| `ReconnectDelayOptions.ladder` | `readonly number[]` | `RECONNECT_LADDER_MS` | Переопределяет ступени. Пустой массив → ошибка. |
| `ReconnectDelayOptions.jitterRatio` | `number` | `0.2` | ±доля разброса вокруг ступени. `0` отключает джиттер (детерминированная ступень). |
| `ReconnectDelayOptions.random` | `() => number` | `Math.random` | Источник случайности в `[0, 1)`. Инъекция для пиннинга джиттера в тестах. |
| `Semaphore` | class | — | Счётный семафор с ограниченной очередью ожидания. Ограничивает и число одновременно исполняемых операций, и число ждущих. |
| `new Semaphore(limit, maxQueued?)` | `(number, number?) => Semaphore` | `maxQueued = limit` | `limit` — сколько слотов выдаётся одновременно (целое ≥ 1). `maxQueued` — глубина очереди (целое ≥ 0); `0` = «не копить, сразу отказ». Невалидные значения → `throw`. |
| `Semaphore.acquire(signal?)` | `(AbortSignal?) => Promise<void>` | — | Берёт слот, встаёт в очередь либо отклоняет. Каждый успешный `acquire()` обязан быть закрыт ровно одним `release()`. |
| `Semaphore.release()` | `() => void` | — | Возвращает слот. Отдаёт его сразу старейшему ждущему (FIFO), а не в счётчик — иначе новый `acquire()` мог бы обогнать очередь. Лишние вызовы не поднимают счётчик выше `limit`. |
| `Semaphore.available` | `number` (getter) | — | Сколько слотов можно взять без ожидания. |
| `Semaphore.queued` | `number` (getter) | — | Сколько живых ждущих в очереди. Отменённые удаляются сразу, поэтому счётчик не врёт. |
| `SemaphoreExhaustedError` | class | — | Кидается из `acquire()`, когда слотов нет и очередь уже на пределе. Поля: `limit`, `maxQueued`. Сигнал сбросить нагрузку. |
| `SemaphoreAbortedError` | class | — | Кидается, когда `signal` сработал, пока вызывающий стоял в очереди. Слот при этом не выдаётся, `release()` не нужен. |

## Приватный контракт

Нет приватного контракта: модуль экспортирует только публичные функции и константы выше; внутренних хелперов и test-only hook'ов нет.

## Архитектурные решения и почему

**Детерминированные ступени + джиттер сверху.** Лестница `[1, 5, 15, 30, 60]` сек фиксирована — поведение реконнекта предсказуемо и одинаково у всех трёх подписчиков. Джиттер (`±20%` по умолчанию) накладывается отдельно в `reconnectDelay`: именно он ломает lockstep, когда сотни клиентов рвут стрим одновременно (общий рестарт рантайма) и иначе ударили бы в рантайм одним синхронным пиком на одной и той же ступени.

**`random` инъектируется.** Джиттер по умолчанию недетерминирован, поэтому тесту, проверяющему точную ступень, нужен способ запиннить случайность — через `opts.random`. Это держит функцию чистой (без скрытого обращения к глобальному `Math.random`) и тестируемой без моков таймера.

**Почему `utils`, а не домен.** Backoff-лестница не принадлежит ни events, ни job, ни workflow, ни telemetry — это общая тайминг-политика без состояния и I/O. Дублировать её в нескольких местах (как было) — рассинхрон-риск; выносить в отдельный «домен» из одной чистой функции — оверинжиниринг. `utils` — единственное разрешённое место для такой доменно-нейтральной чистой логики.

**Семафор ограничивает и конкурентность, и очередь.** Один только лимит конкурентности не защищает от перегрузки: он превращает всплеск нагрузки в неограниченный рост очереди, то есть в рост памяти. Поэтому `maxQueued` — обязательная часть контракта, а не опция: за её пределом `acquire()` отклоняет работу (`SemaphoreExhaustedError`), и вызывающий сбрасывает нагрузку (для RPC-сервера — `RESOURCE_EXHAUSTED`), вместо того чтобы копить то, что всё равно не успеет выполнить.

**`release()` отдаёт слот ждущему напрямую.** Если бы `release()` просто увеличивал счётчик, новый `acquire()` мог бы забрать слот раньше того, кто уже стоит в очереди, — под нагрузкой это голодание ждущих. Передача слота первому в очереди делает порядок FIFO.

**Отмена через `AbortSignal`, а не через таймаут внутри.** Семафор не знает ни про дедлайны вызова, ни про отмену стрима — это доменные понятия. Он принимает готовый сигнал и снимает ждущего с очереди, освобождая место; политику отмены задаёт вызывающий домен.

**Почему семафор — доменно-нейтральный.** Это примитив синхронизации: без состояния предметной области, без I/O, без знания о том, что именно исполняется в слоте. Он подходит под контракт `utils/` по тем же основаниям, что и backoff-лестница.

## Зависимости

- Использует: ничего (`reconnect-ladder` — только `Math`; `semaphore` — только `Promise`/`AbortSignal`).
- Используется: `sdk/node/src/events/subscriber.ts`, `sdk/node/src/job/subscriber.ts`, `sdk/node/src/workflow/subscriber.ts`, `sdk/node/src/registry/watch.ts`, `sdk/node/src/telemetry/transport.ts` (`reconnect-ladder`); `sdk/node/src/rpc/server.ts` (`semaphore`).
